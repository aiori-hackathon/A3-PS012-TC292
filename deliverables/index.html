Authorised DNS Resolver Exposure Assessment

Team Binary Beans, AIORI-3, A3-PS012-TC292. CLI tool v0.1.0, seed final-A.

Nonce-based classification of 20 authorised lab DNS servers into Recursive, Authoritative-only, Refused, Inconclusive. Recursion is proven against the team's own authoritative test-zone log (a unique nonce per target), never inferred from the RA flag, which any server may falsely claim.

Evidence files

terminal-replay.html
Watch the recorded runs: the full demo (self-check, scan, compare, reports), the rate-verification capture, and the kill switch stopping a scan cleanly. Plays in the browser, no setup.
report.html
Full generated report: per-target results with reasons and latency, confusion matrix, canary self-check, remediation for Recursive targets.
results.json  results.csv   evidence.jsonl
Machine-readable outputs. The evidence log holds every probe: qname, flags, rcode, attempts, nonce, and the self-check control record.
stability-summary.json
Three same-seed runs plus one different-seed run: identical labels on all 20 targets, probe attempts per run, self-check verified in each.
rate-verification.json
Captured traffic vs the configured caps: global at or under 5 qps, per-target at or under 1 qps, at most 3 queries per target. 30 DNS questions (29 probes + 1 control query).

Run it yourself (manual setup)

Two prerequisites: Docker (the 22-container lab needs a Docker daemon: 20 targets, the test-zone canary, and the separate client) and uv.

make lab-up make demo

Builds the lab inside your Docker runtime, scans all 20 authorised targets from the dedicated client container, prints the confusion matrix, and writes JSON, CSV, and HTML reports. Without Make: uv run --directory src python run_demo.py.

Notable: the lying resolver (RA=1, fake answer, never recursed) is correctly not labelled Recursive: its nonce never reached the test-zone log (grep count 0). The silent firewall and the packet-loss target are covered in the repo README's repeat-run table.

About the lab: the 20 target containers are Python emulations reproducing the query behaviour of common DNS software (open and closed resolvers, authoritative-only, forwarder, packet dropper, truncation, rate limiter, liar). They are not official BIND, Unbound, NSD, Knot, or PowerDNS images; validating against real upstream images is future work.
Control: every scan opens with a canary attribution self-check. One control query must reach the canary log attributed to the client's own src IP, otherwise the scan refuses to run (see run_metadata.canary_selfcheck). The refused fixtures double as negative controls.
Results establish agreement with this seeded lab, not accuracy on arbitrary production servers. See the README Limitations.
